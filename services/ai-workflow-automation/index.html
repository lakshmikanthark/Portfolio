A small example

From an enquiry

The sample enquiry workflow lets you see how the next action changes when contact details are missing or a request needs attention this week. It uses fictional scenarios and simple rules. It does not connect to a CRM or send messages.

It demonstrates process design and a review step, rather than claiming a finished customer integration or a time-saving result.

How the work is scoped

Map it. Test it.
Keep a person in control.

  1. Understand the current process

    List inputs, tools, people, permissions, recurring steps and the errors that matter.

  2. Choose the right amount of automation

    A clear rule or a better process may be enough. AI is considered where it serves a defined task and the result can be checked.

  3. Build a bounded trial

    Agree example data, expected outputs and recovery cases. Review what happens when information is missing or an external tool is unavailable.

  4. Agree the live responsibilities

    Document approvals, access, tool costs, monitoring, ownership and what happens if a step fails.

Practical questions

Before connecting
your tools.

Which tools can you work with?

Start by sharing your current website, spreadsheets, email and any CRM or other tools you use. Compatibility, account access and the exact integration are reviewed for the brief; support for a particular vendor is not assumed.

Will AI send messages automatically?

The approval boundary is agreed before building. A draft for a person to review and an automatically sent message are different outcomes. The public demonstration only prepares an example draft.

What information should I send first?

A short description of the repetitive task, current tools, approximate frequency, what goes wrong and the result you want. Use anonymised examples rather than passwords or customer records.

Can a website project include a workflow?

Yes, we can discuss the website and the next step together. Explore business website development or read how enquiry stages differ.
